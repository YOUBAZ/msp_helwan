# Events (management, registration, check-in) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dashboard-managed events with public no-account registration, QR tickets, automatic waiting list, door check-in, reminders, and an automatic Upcoming/Live/Past timeline on the Events and home pages.

**Architecture:** New NestJS `events` module (Drizzle tables `events`, `event_registrations`, `event_covers`) with public endpoints (list, detail, register, ticket, cancel), admin endpoints guarded by `events.manage` / `events.checkin`, and a cron endpoint for reminders. Pure time logic lives in `timeline.ts` (unit-tested). Next.js pages read the public API (cached 60 s, live seat state fetched in the browser); a dashboard section manages events, registrations and phone check-in with a JS QR scanner.

**Tech Stack:** NestJS 11, Drizzle, PostgreSQL (Neon / PGlite / Docker), `qrcode` (backend, MIT), Next.js 15, Tailwind v4, `qr-scanner` (frontend, MIT), nodemailer (existing MailService).

**Spec:** `docs/superpowers/specs/2026-11-19-events-design.md`

## Global Constraints

- Time zone for display, input and "next calendar day": `Africa/Cairo`.
- Permissions: `events.manage` (group `Events`, label `Create, edit, publish and cancel events; manage registrations and the waiting list`), `events.checkin` (group `Events`, label `See registrations and check people in at the door`). `events.manage` implies everything `events.checkin` allows.
- Registration fields, all required: name (2–100), email, phone (same rule as profile phone), faculty (2–80), year (1–20 chars). Email trimmed + lower-cased. Honeypot field `website` must be empty (else 400). Throttle register: 5/min/IP.
- One active (non-cancelled) registration per email per event; a repeat returns 409 `You're already registered for this event. We've re-sent your ticket email.` and re-sends the ticket/waitlist email.
- Live window: `startsAt ≤ now < (endsAt ?? startsAt + 3 h)`. Registration closes at `registrationDeadline ?? startsAt`.
- Ticket codes: 32 random bytes base64url, stored as-is (unique). QR content: `${FRONTEND_URL}/tickets/<code>`.
- Covers: one JPEG ≤2 MB (browser makes ≤1600 px via existing `photoVersions().full`), counted in the shared media budget (`MEDIA_BUDGET_BYTES`, default 400 MB) under the same upload lock.
- Public event/cover responses cached like Media (`public, max-age=3600, s-maxage=3600` for covers; pages revalidate 60 s). Event page seat/registration state fetched live in the browser.
- Reminders: endpoint `GET /api/cron/event-reminders`, `Authorization: Bearer ${CRON_SECRET}` (401 otherwise); backend `vercel.json` crons at `0 6 * * *` and `0 9 * * *` (UTC). Stop sending after 40 s; per-registration `reminder_sent_at`.
- Seed (migration): 4 published past events — `Orientation Day 2025` 2025-06-23, `Battery Tech with Schneider Electric 2025` 2025-07-17 (highlight `Industry Certification`), `AI Catalyst with Dotpy 2025` 2025-08-22 (highlight `200+ Attendees`, manual attendance 200), `Season Orientation 2026` 2026-03-01 at `Main Hall, Capital University`; all 10:00 Cairo, registration disabled; descriptions copied from `frontend/src/data/events.ts`. `upcomingEvents`/`pastEvents` are then removed from that file.
- Every change passes: backend `npx tsc --noEmit`, eslint, `npx jest`, `npm run test:e2e`; frontend `npm run lint`, `npx tsc --noEmit`.

## Review Focus

1. **Two people taking the last seat at the same moment** → exactly one confirmed, one waitlisted. (Task 4 e2e `gives the last seat to only one person`, also run on Docker Postgres.)
2. **The same email typed with different case/spaces** → treated as the same person (409 + re-send). (Task 4 e2e.)
3. **Events just after midnight Cairo** (e.g. 00:30 Cairo = 22:30 UTC the day before) → reminded on the correct Cairo day. (Task 1 unit test `tomorrowInCairo handles UTC/Cairo day boundary`.)
4. **A ticket for a different event scanned at the door** → "wrong event", not checked in. (Task 5 e2e.)
5. **Cancelling after the event has started** (self or by manager on a past event) → refused with a clear message. (Task 4 e2e.)

**Interfaces — Produces:**
